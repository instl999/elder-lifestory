# 测试样本：用真实的普通话测量转写效果

[English](README.md) | 简体中文

`evaluate_asr.py` 在本机转写一段录音，再拿它和一份已知的文本对比打分。需要判断某个 Whisper 模型够不够用时，
或者手上有一次真实访谈、并且有一份人工校正过的转写稿可以对照时，都可以用它。

```bash
python samples/evaluate_asr.py <音频> <参考文本.txt> --language zh --model small \
    --hint "已知的,人名,地名" --save samples/zh/transcript.txt
```

它报告两个数字：

- **CER（字错误率）**：按汉字计算（其他语言按词计算）。两端对齐不计代价，所以参考文本里没有的开场白，不会算作模型的错误。
- **人名召回率**：参考文本里的专有名词，有多少个一字不差地转写对了。对回忆录来说，这才是要紧的数字：
  §18 把人名列为“零错误”项目，一个整体 CER 很低、但错误全落在人名上的结果，比一个 CER 稍高、人名却全对的结果更糟。

加上 `--save` 时，转写会分段存盘，中断后可以接着转。

## 测试录音

**鲁迅《朝花夕拾》，LibriVox 志愿者 Jing Li 的普通话朗读。** 这是一部童年回忆录，写保姆阿长、百草园、
父亲的病与死，正是 LifeStory 要处理的那一类材料。

| | |
|---|---|
| 录音 | [archive.org/details/chao_hua_si_she_jl_librivox](https://archive.org/details/chao_hua_si_she_jl_librivox) |
| 授权 | 公有领域标志 1.0（LibriVox 的录音都贡献给公有领域） |
| 文本 | 公有领域（鲁迅于 1936 年去世）；参考文本取自 [zh.wikisource.org](https://zh.wikisource.org)，统一转为简体 |
| 使用 | 第 02 篇《阿长与〈山海经〉》（12:36）和第 07 篇《父亲的病》（11:43） |

音频文件不放进仓库。下载方法：

```bash
curl -L --ssl-no-revoke -o samples/zh/chaohuasishe_02_lu_64kb.mp3 https://archive.org/download/chao_hua_si_she_jl_librivox/chaohuasishe_02_lu_64kb.mp3
```

```bash
curl -L --ssl-no-revoke -o samples/zh/chaohuasishe_07_lu_64kb.mp3 https://archive.org/download/chao_hua_si_she_jl_librivox/chaohuasishe_07_lu_64kb.mp3
```

**这份样本说明不了什么。** 它是一位训练有素的朗读者在念一篇准备好的文章，而不是和一位八十岁老人的即兴对谈。
真实访谈的分数会更低：老人的嗓音、地方口音、说了一半又重来、两个人同时说话。它也测不了说话人标签，
因为只有一个人在说。请把下面的数字当作上限，一有真实访谈就去测。

**为什么不用老年人语音语料库？** 最合适的那个，SeniorTalk（202 位 75–85 岁的说话人，覆盖 16 个省份），
在使用条款里禁止“商业产品开发”，而 LifeStory 是收费产品。它在 Hugging Face 上的标签写的是 Apache-2.0，
但以数据集自己的条款为准。大多数中文语音语料库都有同样的非商用限制。

## 结果

在这台电脑上测得（4 个 CPU 核心，同时在跑别的任务，所以速度会有波动）。CER 计入每一个字；
“人名正确”使用 `zh/names_02.txt` 和 `zh/names_07.txt` 里固定的人名列表。

| 篇目 | 模型 | 提示词 | CER | 人名正确 | 速度 |
|---|---|---|---|---|---|
| 02 阿长与《山海经》 | `base` | — | 15.0% | — | 实时的 0.40 倍 |
| 02 | `small` | — | **11.0%** | — | 0.88 倍 |
| 02 | `small` | 鲁迅、长妈妈、阿长、绍兴 | 11.4% | 5 / 13 | 0.63 倍 |
| 07 父亲的病 | `small` | 鲁迅、绍兴、衍太太 | 16.2% | 4 / 9 | 1.10 倍 |

**中文默认用 `small`。** 它比 `base` 少了大约四分之一的错误；`base` 把这本书自己的书名“朝花夕拾”转成了“招花西石”。

**几乎每个错误都是同音字。**“憎恶”被转成了“赠物”，“陈莲河”被转成了“陈连河”和“陈联合”，“凭票付英洋”被转成了
“冯瓢复英扬”，“衍太太”被转成了“眼太太”。中文识别是按读音出错的，所以核对清单按拼音把名字归组。

**核对清单指向的是真错误。** 在第 07 篇里，清单的 11 个条目中有 7 个是名字的真实误听，每个都附有可以直接跳过去听的时间点：
陈连河 ×3、陈联合、宣元齐伯（轩辕岐伯）、卢根 ×2（芦根）、冯瓢（凭票），以及归在“衍太太”名下的“眼太太”。
其余的是值得确认的正确名字，外加一个误报。它抓不到普通词语的错误（“赠物”代替“憎恶”），只有跟着录音通读才能发现。

**提示词有一点帮助，也可能误导。** 在一段 80 秒、第一遍转错了七个名字的片段上，提示正确的写法后多对了一个
（不加提示对 1 个，加了对 2 个）。而且一个提示词“茉莉”被写进了片段开头，那里根本没说这个词。
所以提示过的名字会在核对清单上单独标出，和其他名字一样需要确认。

**中断的转写可以接着来。** 第 02 篇故意在 3:05 处被强行中止，重新启动后从断点接着转，最终的 CER 和一次跑完的结果相同。

### 用这两篇做成一本书

`zh/run_demo.py` 把这两份转写稿走完工作台的每一条命令，最后生成一本中文 DOCX（大约 10 分钟，使用 `.env` 里的 API 密钥）。
它做出来的书在 [`zh/demo_book/`](zh/demo_book/) 里，仔细通读后发现了什么，见主 README 的[演示一节](../README.zh-CN.md#普通话演示从录音到成书)。
脚本会创建 `cases/luxun-demo`，用完请删掉，以免它被计入 `portfolio` 统计。
